# 1.35 Development

分支 / Branch: `Pre-1.35` · 2026-09-28

## 中文

第一阶段已将插件常驻进程管理迁到 Rust：读取与校验 JSON 行、转发诊断、检测超时和断管、退出时清理插件进程组。Python 继续完成插件包、配置和翻译准备，再用 `exec` 替换为 Rust 运行器；插件本体仍可使用 Python。桌面和设置 GUI 尚未迁移。

插件列表在名称旁显示带代表色的圆角标签（例如 `+ Python`），按插件声明的实现语言显示，不把 Python 插件标为 Rust。旧版原生二进制只声明 `binary` 时显示“原生 / Native”，不猜测其源码语言。标签保留固定内容宽度，插件名称按需省略，按钮仍可使用。

源码安装会构建并原子安装运行器；Arch 预构建流程增加运行器及 SHA-256 校验，仍不要求目标用户安装编译器。源码与预构建更新流程均支持准备运行器。程序内的 `libexec/adws-plugin-runner` 会随更新整体备份/替换，安装失败时也会恢复。

- `ADWS_PLUGIN_RUNNER=auto`（默认）：存在运行器时使用 Rust，否则回退 Python。
- `ADWS_PLUGIN_RUNNER=rust`：明确要求 Rust；缺少二进制时报告错误。
- `ADWS_PLUGIN_RUNNER=python`：明确使用 Python 回退。该后端的退出信号等待问题也已修复。

运行器优先查找 `libexec/adws-plugin-runner`，其次是源码 release 构建目录。后端在插件进程启动时确定；已运行的插件要随任务栏重启才切换。不要直接用内部 `--spec-json` 接口运行普通插件。

开发构建与试用（Rust 1.87+）：

```sh
cargo build --release --locked --manifest-path src/adws-runtime/Cargo.toml
ADWS_PLUGIN_RUNNER=rust ./adws mplg run /path/to/plugin.mplg
```

验证：

```sh
cargo test --locked --manifest-path src/adws-runtime/Cargo.toml
cargo clippy --locked --manifest-path src/adws-runtime/Cargo.toml --all-targets -- -D warnings
python3 -m unittest discover -s tests -v
GDK_BACKEND=x11 xvfb-run -a python3 tests/check_plugin_settings_gui.py
```

先构建 release 再运行 Python 测试，才能执行原生进程集成测试；未构建时这些测试会跳过。覆盖正常/异常输出、设置传参、暂停、超时、慢消费者、断管、信号退出、默认选择和回退，以及安装与更新中的可执行权限和校验失败保护。

Rust 使用严格 JSON 解析，并限制过深嵌套、单行长度和输出队列，不保证接受 Python 解析器曾容忍的非标准 JSON。这一阶段迁移的是运行器，不代表所有插件、GUI 和安装器已经改写，也不能将合成测试的改善比例套用到整个桌面。

安装增加“灵魂拷问”：检测 SSH 环境变量、TTY 会话，或没有 Wayland/X11 显示变量时，先询问是否继续，默认取消。确认后才开始依赖检查及安装事务；递归执行安装事务不会重复询问。普通桌面终端不会询问，帮助命令不触发确认。

## English

The first stage moves resident plugin supervision to Rust: JSON-lines validation, diagnostic forwarding, timeout and disconnect handling, and process-group cleanup. Python still prepares packages, settings and translations, then uses `exec` to replace itself. Plugin implementations, the desktop and settings UI have not been rewritten.

Colored language badges beside plugin names describe their declared implementation, independently of the supervisor. Legacy `binary` entries are labeled Native without guessing their source language. Long names remain ellipsized and action buttons stay visible.

Source installation builds and atomically installs the supervisor. Arch packaging includes the executable and SHA-256 verification without requiring a compiler on the target machine. Source/prebuilt update preparation also stages it. Installation rollback and whole-program update backups cover `libexec/adws-plugin-runner`.

`ADWS_PLUGIN_RUNNER=auto` is the default: prefer Rust when available, otherwise use Python. Explicit `rust` fails if the executable is missing; explicit `python` selects the fallback. Python's termination-signal delay has also been fixed. Backend selection occurs at process startup, so running plugins require a taskbar restart to switch.

The executable is resolved from `libexec` first, then the release build directory. Build with Rust 1.87+ and use the commands above. Build release mode before Python tests; native integration tests otherwise report skips. The private `--spec-json` interface is not a public plugin command.

Strict JSON parsing, nesting limits and bounded line/output queues may reject nonstandard input tolerated by Python. Synthetic supervisor results do not measure total desktop performance.

Installation asks for confirmation in SSH, TTY or sessions without Wayland/X11 display variables, defaulting to cancellation before dependency or configuration changes. Confirmed installation transactions do not ask twice; desktop terminals and help commands are unaffected.
