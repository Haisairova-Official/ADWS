# 待复现：部分安装环境加载 Waybar include 配置失败

报告日期：2026-09-14。状态：已实现兼容性处理，待 Ubuntu 实机验证；尚未确认底层根因；未提交到 GitHub Issues。

## 用户报告

截图中的排查建议将 `"include": ["modules.jsonc"]` 改为使用绝对路径的字符串，并认为 ADWS 不支持数组。截图没有包含原始错误日志，因此这个原因尚不能确认。

## 已核实

- 当前默认配置使用数组形式的 include。
- `tools/adws_health.py` 的校验器和 `tools/adws_layout.py` 的启动器读取逻辑都处理字符串和数组。
- 临时目录中分别验证了相对路径字符串、相对路径数组、绝对路径字符串、绝对路径数组；四种形式均通过配置校验，并正确读取启动命令。没有修改用户当前配置或重启任务栏。
- 本机 Waybar 手册明确标注 include 类型为 `string|array`。

## 下一步所需证据

用户补充：问题出现在 Ubuntu 构建环境，将单个默认 include 改为绝对路径字符串后可稳定解决。本机 Arch 不复现。

## 已实现的兼容处理

- 安装时，将单个默认 `modules.jsonc` 引用转换成配置安装目录下的绝对路径字符串，遵循 XDG_CONFIG_HOME。
- 更新前创建 `.adws-include-bak`，保留配置软链接和其他设置、注释；重复安装不重复改写。
- 布局生成同样使用绝对路径字符串，避免应用布局后重新出现问题。
- 用户自定义单文件引用和多文件 include 保持原样。仍保留字符串、数组解析支持。
- 临时目录中的安装、路径含空格、配置软链接、注释保留、重复运行与布局生成测试通过。尚未在用户的 Ubuntu 环境验证。

## 待确认的底层原因

出问题环境的 `adws -v`、`waybar --version`、`adws check` 输出及原始启动错误日志；配置文件实际位置、include 内容和启动时的工作目录。

进一步单独改变格式或路径，才能区分底层路径和格式兼容原因。目前按用户已验证的方式处理默认配置，不将其解释为普遍不支持 include 数组。

## 验收目标

安装后从不同工作目录启动，字符串与数组 include 均可加载；缺失引用文件时明确报告引用来源和解析后的路径。
